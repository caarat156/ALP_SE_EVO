# EVO Project: Bug Reports & Feature Fixes

Dokumen ini merangkum 8 isu kritikal hingga menengah yang ditemukan pada sistem EVO, lengkap dengan penyebab dan panduan solusi teknis berdasarkan arsitektur 3-Tier (Client, Application, Data).

## Kategori 1: Logika Bisnis & Integritas Data (Prioritas Kritis)

### 1. Hubungan Akun Vendor & Objek Vendor Terputus
* **Lokasi:** `SampleData.swift` (L22, L102), `VendorViews.swift` (L31)
* **Penyebab:** Ketidakcocokan antara ID User Auth (`vendor123`) dengan ID objek bisnis Vendor (`vendor1`, `vendor2`). *Query* *invoice* gagal memetakan pemilik.
* **Solusi:** Sinkronkan entitas. Saat akun vendor dibuat via Cloud Functions, pastikan profil bisnis Vendor ditautkan ke ID *User Auth* (UID) yang sama agar *query* berjalan akurat.

### 2. Kebocoran Kuota Tiket (Overbooking)
* **Lokasi:** `FirebaseService.swift` (L150 - `registerEventForPeserta`)
* **Penyebab:** Penambahan `registeredCount` dilakukan *client-side* tanpa validasi kuota secara *real-time*, rentan *race condition* saat *traffic* tinggi.
* **Solusi:** Pindahkan logika pendaftaran ke Firebase Cloud Functions menggunakan operasi **Firestore Transaction**. Transaksi harus menolak pendaftaran jika `registeredCount >= quota`.

### 3. Input Harga Barang Vendor Bernilai Nol/Negatif
* **Lokasi:** `VendorViews.swift` (L157 - `AddCatalogItemView.addItem()`)
* **Penyebab:** Hanya memvalidasi tipe `Double`, tanpa mengecek batas minimum nilai.
* **Solusi:** Tambahkan validasi di Application Tier (Cloud Functions) dan penanganan *error* di Client Tier (`guard priceDouble > 0 else { ... }`).

## Kategori 2: Keamanan & Hak Akses (Prioritas Tinggi)

### 4. QR Code Rentan & Terlihat Seperti Placeholder
* **Lokasi:** `PesertaViews.swift` (L458), `FirebaseService.swift` (L507)
* **Penyebab:** QR Code berisi *string* Base64 mentah yang mudah dipalsukan. UI menampilkan ID statis (contoh: "event1") bukan nama acara.
* **Solusi:** Terapkan skema kriptografi (misal: JWT atau HMAC-SHA256) di Cloud Functions untuk *generate token* QR. Perbarui UI SwiftUI agar menarik relasi nama *event* dan nama peserta secara dinamis.

### 5. Akses Feedback Ilegal (Tanpa Kehadiran)
* **Lokasi:** `PesertaViews.swift` (L249 - `EventDetailView`)
* **Penyebab:** Tombol "Leave Feedback" muncul hanya berdasarkan status *event* (`.completed`), bukan status kehadiran tiket peserta.
* **Solusi:** Sembunyikan tombol "Leave Feedback" jika `ticket.status != .used` (belum *check-in*).

## Kategori 3: UI/UX & Fungsionalitas Tambahan (Prioritas Menengah)

### 6. Layar Brightness Tersangkut di 100%
* **Lokasi:** `PesertaViews.swift` (L485-L489 - `QRCodeDisplayView`)
* **Penyebab:** `.onAppear` menaikkan *brightness* layar, tetapi `.onDisappear` tidak mengembalikannya ke nilai awal.
* **Solusi:** Simpan nilai *brightness* pengguna saat ini ke dalam `@State private var originalBrightness: CGFloat`, lalu terapkan kembali nilai tersebut pada blok `.onDisappear`.

### 7. Absennya Live Dashboard untuk Panitia
* **Lokasi:** `PanitiaViews.swift` (L46 - `PanitiaDashboardView`)
* **Penyebab:** *Dashboard* bersifat statis tanpa fitur pemantauan *real-time* untuk acara berstatus `.ongoing`.
* **Solusi:** Buat `LiveMonitoringView` yang menggunakan *snapshot listener* Firestore untuk memantau pembaruan `checkInCount` dan analitik *feedback* secara seketika (*real-time*).

### 8. Ketiadaan Fitur Reputasi/Rating EO
* **Lokasi:** `PesertaViews.swift` (L334 - `FeedbackFormView`)
* **Penyebab:** *Feedback* hanya melekat pada *event*, tidak ada agregasi nilai reputasi untuk profil spesifik Event Organizer (EO).
* **Solusi:** Buat skema sub-koleksi *rating* pada profil Panitia/EO. Setiap peserta yang menyelesaikan *feedback* *event* dapat memberikan ulasan terpisah untuk kinerja penyelenggara.
